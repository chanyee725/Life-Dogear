# PLAN-PAGES — 문서 안 노트 + `/` 명령

기준: develop 9799803. 구현자 1 + 리뷰어 1.

## 1. 상세 화면 '노트' 섹션

- 공용 컴포넌트 `ItemNotes`(가칭) 하나를 프로젝트·영역·목표 상세에 같은 모양으로 넣는다.
  - 프로젝트·목표: `links`로 연결된 노트. 영역: `notes.area_id` + links(중복 제거).
  - 행: 제목 · 수정일(공용 `ListRow`·`format`). 보관된 노트 제외.
  - 비었으면 공용 `EmptyAdd` 점선 박스 "＋ 새 노트".
- "새 노트" → `/notes/new?project=<id>`(또는 `area=`/`goal=`). 템플릿 선택 화면은 그대로 두고, 저장할 때 연결(영역은 `area_id`).
- 프로젝트는 노트에 따로 프로젝트 칸이 없으므로 "노트의 프로젝트" = `links` 연결.

## 2. 에디터 `/` 명령

- Tiptap 확장 + 메뉴 컴포넌트 `SlashMenu`. 위치·키 처리는 `WikiSuggest` 방식을 따른다.
- 뜨는 조건: 줄 맨 앞이나 공백 뒤에서 `/`. 코드 블록·인라인 코드 안에서는 안 뜸. `[[` 제안이 열려 있으면 안 뜸.
- 항목: 페이지, 제목 2, 제목 3, 목록, 번호 목록, 할 일, 인용, 코드, 표, 사진.
- 키: ↑↓ Enter Esc. 입력으로 필터(한글·영문 별칭: 페이지/page, 할 일/todo, 제목/h2·h3, 목록/list·bullet, 번호/ol·number, 인용/quote, 코드/code, 표/table, 사진/image).
- 선택 시 `/검색어`를 지우고 블록으로 바꾼다. 사진은 기존 이미지 업로드 경로.
- 페이지: 메뉴 안에서 제목 입력 → 서버 액션으로 노트 생성 + 지금 문서와 link(영역이면 `area_id`도) → 커서에 `[[제목]]`.
  - 에디터는 지금 문서의 (type, id)를 prop으로 받는다. 없으면(`/new` 화면) '페이지' 항목을 숨긴다.

## 3. 사이드바 (결정 대기)

상단 "회고"를 "노트"로 바꿀지 사용자에게 묻는다. 구현은 1·2 뒤.

## 규칙

공용 ui, 짧은 문구, headless만, `loading.tsx` 금지, push 금지. 단위 테스트(필터·뜨는 조건) + e2e(프로젝트 노트 섹션, `/` → 제목 2, `/` → 페이지 생성·링크).
