# 계획: 인생 목표 + Obsidian식 그래프 (단계 G)

> 사용자 요청 (2026-11-02): "PARA를 참고해서 내 인생의 목표와 모든 것을 Obsidian처럼 그래프로 정리할 수 있게."
> 근거 문서: `docs/PROPOSAL-SECOND-BRAIN.md`(3절 목표, 6절 데이터), `docs/PLAN-1.5.md`(현재 PARA 뼈대).
> 사용자 승인 전에는 구현하지 않는다.

## 0. 한 줄 요약

목표를 **인생 → 연 → 분기** 3단으로 세우고, 목표·영역·프로젝트·자료·생각을 모두 노드로 하는 `/graph` 화면을 만든다.
연결은 기존 `links`와 소속 관계(프로젝트→영역/목표 등)를 그대로 쓰고, 본문에 `[[제목]]`을 쓰면 연결이 생기게 한다.

## 1. 원칙

1. **새 저장소 없음.** 그래프는 기존 테이블에서 계산한다. 그래프만을 위한 테이블은 만들지 않는다(노드 위치 고정 저장만 예외, 4절).
2. **모든 데이터는 로컬.** 그래프 라이브러리는 번들에 포함하고 외부 서버를 부르지 않는다.
3. **조용한 디자인 유지.** 무채색 노드 + 목표만 포인트 색. 라벨은 확대하거나 hover할 때만.
4. **매일 쓰는 흐름 우선.** 큰 그래프보다 "이 항목 주변"(로컬 그래프)을 더 자주 본다.

## 2. 목표 (그래프의 뿌리)

PROPOSAL 3절의 목표 설계에 **인생 목표** 한 단을 더한다.

| 단 | 기간 값 | 예 | 부모 |
|---|---|---|---|
| 인생 목표 | 없음(`life`) | "좋은 연구자가 된다", "건강하게 오래 산다" | 없음 |
| 연 목표 | `2027` | "1저자 논문 1편 게재" | 인생 목표(선택) |
| 분기 목표 | `2027-Q1` | "학회 제출본 완성" | 연 목표(선택) |

- 프로젝트는 목표 하나를 향한다(`projects.goal_id`). 목표는 영역 하나에 속할 수 있다(`goals.area_id`).
- 진행률: 분기 = 연결된 프로젝트 완료 비율(없으면 수동), 연 = 하위 분기 평균, 인생 = 진행률 없음(방향만).
- 화면: `/goals` — 인생 목표를 맨 위에 두고 그 아래 연·분기를 접히는 트리로. 목표 상세는 다른 상세 화면과 같은 레이아웃.

## 3. 그래프에 무엇이 들어가나

**노드**: 목표, 영역, 프로젝트, 논문, 세미나, 생각. (선택) 주제(태그). 보관한 항목은 기본 숨김.

**선 (edge)**

| 종류 | 출처 | 모양 |
|---|---|---|
| 소속 | 분기→연→인생 목표, 프로젝트→목표, 프로젝트→영역, 목표→영역 | 진한 실선 |
| 연결 | 기존 `links` (상세 화면 "연결된 항목") | 얇은 실선 |
| 본문 링크 | 본문의 `[[제목]]` (5절) | 얇은 실선 (연결과 같게) |
| 주제 | 항목↔태그 (주제 노드를 켰을 때만) | 점선 |

## 4. 화면

**`/graph` 전체 그래프** (사이드바에 "그래프" 추가)
- 힘 기반 배치(Obsidian과 같은 방식). 노드 크기 = 연결 수, 색 = 종류(무채색 단계), 목표만 포인트 색.
- hover: 이웃만 밝게, 나머지 흐리게. 클릭: 오른쪽 패널에 미리보기 → "열기"로 상세 이동.
- 왼쪽 위 필터: 종류 체크, 영역 선택, 주제 선택, "보관 항목 보기", "연결 없는 항목만"(정리할 것 찾기).
- 보기 전환: **[자유 배치 | PARA 배치]**. PARA 배치는 왼쪽부터 목표 → 영역 → 프로젝트 → 자료(논문·세미나) → 생각 열로 고정해서 "인생 목표에서 오늘 읽는 논문까지" 흐름이 한눈에 보이게 한다.
- 노드를 끌어 놓은 위치는 기억한다(그래프 전용 작은 테이블 `graph_layout`: node, x, y). 초기화 버튼 있음.
- 단축키 `G`: 그래프 열기, 그래프 안에서 `/`: 노드 검색 후 그 노드로 이동.

**로컬 그래프** (모든 상세 화면 오른쪽 아래, 접을 수 있음)
- 이 항목 기준 1단계 이웃(토글로 2단계). 클릭하면 그 항목으로 이동.

**목표 지도** (`/goals` 안의 탭)
- 그래프가 아닌 트리: 인생 목표 → 연 → 분기 → 프로젝트 → (연결된 자료 개수). 그래프가 복잡할 때 같은 구조를 글로 본다.

```
┌ 그래프 ─────────────────────────────── [자유 배치 | PARA 배치] ┐
│ 종류 ☑목표 ☑영역 ☑프로젝트 ☑논문 ☑세미나 ☑생각 ☐주제          │
│ 영역 [전체 ▾]  ☐ 보관 보기  ☐ 연결 없는 항목만                  │
│                                                                 │
│        ● 좋은 연구자          ○ 논문 A ── ○ 생각                │
│         ╲                    ╱                                  │
│          ● 1저자 논문 ── ◇ 연구 X ── ○ 세미나 B                 │
│                          ╲                                      │
│                           □ 영역: 연구 분야      ┌ 미리보기 ──┐ │
│                                                  │ 연구 X      │ │
│                                                  │ 다음 할 일… │ │
│                                                  │ [열기]      │ │
│                                                  └─────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

## 5. `[[위키링크]]` (Obsidian식 본문 링크)

- 에디터에서 `[[` 입력 → 제목 검색 팝업(기존 LinkPicker 검색 재사용) → 고르면 `[[제목]]`이 들어가고 클릭하면 그 항목으로 이동.
- 저장할 때 본문의 `[[...]]`를 `links`에 반영한다(출처 표시 `via='body'`). 본문에서 지우면 그 연결도 지운다. 사람이 직접 만든 연결(`via='manual'`)은 건드리지 않는다.
- 제목이 바뀌면 다른 본문의 `[[옛 제목]]`도 바꿀지: 기본은 "바꾸기" 확인 창.
- 없는 제목을 쓰면: 회색으로 표시하고 클릭 시 "생각으로 만들기".

## 7. 기술 선택 (권장)

| 항목 | 권장 | 다른 안 |
|---|---|---|
| 그래프 렌더링 | `react-force-graph-2d` (canvas + d3-force, 수천 노드 무난, Obsidian 느낌과 가장 가까움) | `sigma.js + graphology` (WebGL, 1만+ 노드에 유리하지만 설정이 많음) |
| PARA 배치 | d3-force에 열(x) 고정 힘을 더해 구현 | 별도 레이아웃 라이브러리 |
| 위키링크 | Tiptap 확장(제안 팝업) | — |

## 8. 단계와 담당 (1팀)

1. **G1 목표** — 구현자 A: `goals` 스키마·repo·`/goals`(트리)·목표 상세, 프로젝트에 목표 선택. 리뷰 후 병합.
2. **G2 그래프 데이터** — 구현자 B: `{nodes, edges}` 계산(소속·연결·주제), 필터, `graph_layout` 저장 API. G1과 동시에 시작(목표 노드는 인터페이스로 먼저).
3. **G3 그래프 화면** — 구현자 C + 디자이너: `/graph`(자유·PARA 배치, 미리보기, 필터), 상세 화면 로컬 그래프, 단축키.
4. **G4 위키링크** — 구현자 A(G1 뒤): 에디터 `[[` 제안, 저장 시 `links` 동기화, 제목 변경 처리.
5. 테스트·문서 → 전체 점검 → 보고.

- 2팀의 검색·하이라이트 통합(진행 중)과 파일이 겹치는 곳: 사이드바(그래프 메뉴 추가), 논문 상세. 2팀 병합이 먼저 들어간 뒤 G3를 붙인다.
- 주간 검토·디스코드 알림은 이 단계에 넣지 않는다(디스코드 결정 대기).
