# Research Brain

논문, 세미나 노트, 내 생각, 내 연구 프로젝트를 한곳에서 관리하는 개인용 연구 노트 웹앱입니다. 노션에서 옮겨 오는 것을 전제로 조용한 디자인과 PDF 이어 읽기를 핵심으로 합니다. 혼자 쓰는 앱이며 내 컴퓨터에서 실행합니다.

## 요구사항

- Node.js 22.12 이상의 22.x 또는 24 이상 (검증은 Node 24에서 합니다)
- npm (이 프로젝트는 `package-lock.json`으로 의존성을 고정합니다)

## 한 번에 설정 (새 PC)

```bash
git clone -b develop https://github.com/chanyee725/Life-Dogear.git && cd Life-Dogear
bash scripts/setup.sh --start          # 샘플 데이터까지: --seed
```

Node 확인(없으면 nvm으로 24 설치) → `npm ci` → `.env` 준비(값은 직접 입력) → `data/pdfs` 생성 → `db:migrate` → 프로덕션 빌드(`.next-prod`)를 차례로 하고, `--start`면 `http://127.0.0.1:3100`에 띄웁니다. 다시 실행해도 안전합니다(기존 `.env`는 그대로 둠). 옵션은 `bash scripts/setup.sh --help`.

## 설치

```bash
npm ci
```

## 환경 설정

설정은 `.env` 또는 `.env.local`에 둡니다. `.env.example`을 복사해서 만들고, 값은 직접 입력합니다. 이 파일들은 절대 커밋하지 않습니다 (`.gitignore`에 포함되어 있습니다).

```bash
cp .env.example .env
```

- **로컬 모드 (기본):** `DATABASE_URL`을 비워 두면 `file:./data/local.db` 로컬 SQLite 파일을 사용합니다. 별도 설정이 필요 없습니다.
- **Turso 모드:** `DATABASE_URL`에 Turso 데이터베이스 주소, `DATABASE_AUTH_TOKEN`에 토큰을 넣으면 Turso를 사용합니다. 두 값을 모두 채워야 합니다.
- **`DATA_DIR`(기본 `data`):** 로컬 `local.db`와 `pdfs/`·`images/` 폴더가 놓일 위치를 바꿉니다.
- **공유 파일 저장소 (`S3_*`, 선택):** 사진과 PDF를 Cloudflare R2(또는 S3 호환 버킷)에 둡니다. 아래 [공유 파일 저장소](#공유-파일-저장소-cloudflare-r2) 참고.
- **`ALLOWED_HOSTS`:** 서버가 받아들일 접속 주소입니다. 쉼표로 구분하며, `name`은 모든 포트를, `name:port`는 그 포트만 허용합니다. 기본 허용은 `127.0.0.1`, `localhost`, `[::1]`입니다. 허용되지 않은 주소로 접속하면 403 안내가 나옵니다. 값을 바꾸면 서버를 재시작해야 반영됩니다.

## 데이터베이스 준비

```bash
npm run db:migrate
```

`drizzle/` 폴더의 마이그레이션 SQL을 현재 DB에 적용합니다. 새로 설치했거나 DB 구조가 바뀐 뒤에 실행합니다.

> **Turso 모드 주의:** `db:migrate`와 `db:seed`는 설정된 Turso 데이터베이스를 대상으로 실행됩니다. 샘플 데이터도 원격 DB에 들어갑니다.

### 샘플 데이터 (선택)

```bash
npm run db:seed
```

연구, 논문, 세미나, 생각, 태그, 연결 등 샘플 데이터를 넣고 `data/pdfs/`에 더미 PDF를 만듭니다. seed- 접두 샘플 항목만 지우고 다시 넣습니다(직접 만든 항목은 유지). 그래도 실행 전에 [데이터 백업](#데이터-백업)을 권장합니다.

> **주의:** 쓰기 직렬화가 한 프로세스 안에서만 적용되어, dev 서버와 동시에 쓰면 `SQLITE_BUSY`가 날 수 있습니다. 개발 서버(`npm run dev`)를 끈 상태에서 실행하세요.

## 실행

```bash
npm run dev
```

브라우저에서 <http://127.0.0.1:3000>을 엽니다. 기본 허용 주소는 `127.0.0.1`, `localhost`, `[::1]`이며, 다른 주소는 `ALLOWED_HOSTS`에 추가합니다. `ALLOWED_HOSTS`를 바꾸면 서버를 재시작해야 반영됩니다.

## PDF·사진 저장 위치

기본은 로컬입니다. 논문 PDF는 `data/pdfs/<논문 id>.pdf`, 본문에 붙인 사진은 `data/images/<임의 이름>`에 저장하며 위치는 `DATA_DIR`로 바꿀 수 있습니다. 파일 이름은 사용자가 정한 이름이 아니라 논문 id나 임의 이름으로 정해집니다.

### 공유 파일 저장소 (Cloudflare R2)

Turso로 PC 두 대가 DB를 같이 쓰면, 로컬 모드에서는 다른 PC에서 올린 PDF·사진이 보이지 않습니다. R2 버킷을 설정하면 모든 PC가 같은 파일을 봅니다. 브라우저는 지금처럼 `/api/images/...`, `/api/papers/<id>/pdf`로 받고 서버가 버킷에서 가져와 전달하므로, 버킷을 공개할 필요가 없고 키도 브라우저에 노출되지 않습니다.

1. Cloudflare 대시보드 → **R2** → **Create bucket** (예: `research-brain`). 공개 접근은 켜지 않습니다.
2. **R2** → **Manage R2 API Tokens** → **Create API token**: 권한 **Object Read & Write**, 대상은 방금 만든 버킷만. 발급된 Access Key ID와 Secret Access Key를 복사합니다 (Secret은 한 번만 보입니다).
3. 각 PC의 `.env`에 네 값을 모두 넣습니다. 하나라도 비면 로컬 모드입니다.

   ```bash
   S3_ENDPOINT=https://<계정 ID>.r2.cloudflarestorage.com
   S3_BUCKET=research-brain
   S3_ACCESS_KEY_ID=...
   S3_SECRET_ACCESS_KEY=...
   # S3_REGION은 비워 두면 auto (R2는 그대로 두면 됩니다)
   ```

4. 서버를 다시 시작합니다. 이후 올리는 파일은 버킷에 저장됩니다.
5. 전에 로컬에 올린 파일은 그 PC에서 한 번 버킷으로 옮깁니다. 이미 버킷에 있는 파일은 건너뜁니다.

   ```bash
   npm run storage:push -- --dry-run   # 올릴 개수만 확인
   npm run storage:push
   ```

옮기기 전에도 버킷에 없는 파일은 그 PC의 로컬 폴더에서 읽으므로 깨지지 않습니다. 로컬 파일은 지우지 않으니, 옮긴 뒤 확인하고 직접 정리하세요. 결과는 개수만 출력하며 키·주소·파일 이름은 출력하지 않습니다.

### 안 쓰는 사진 정리

본문에서 지운 사진은 파일로 남습니다. 아래 명령은 어떤 본문에서도 참조하지 않고, 만든 지 24시간이 지난 사진만 찾습니다(갓 붙인 사진은 저장 전일 수 있어 건너뜀). 기본은 개수만 보여 주고, `--apply`를 붙여야 지웁니다. 지운 사진은 되돌릴 수 없으니 먼저 [데이터 백업](#데이터-백업)을 권장합니다.

```bash
npm run storage:gc-images            # 지울 개수 확인 (dry-run)
npm run storage:gc-images -- --apply # 실제 삭제
```

공유 저장소를 쓰는데 DB가 로컬 파일이거나, 참조된 사진이 하나도 없으면(DB 설정 실수 가능성) 삭제하지 않고 멈춥니다. 첫 줄에 저장소 종류(local/s3)와 DB 종류(local/turso)를 주소 없이 보여 줍니다.

> 앱을 쓰는 중에는 실행하지 마세요. 모든 PC에서 서버를 끈 상태에서 실행합니다. 편집 중인 본문의 사진이 지워질 수 있습니다.

## 단계별 범위

### 1단계 MVP (현재 구현 범위)

- 데이터 모델: 연구, 논문, 세미나, 생각 4개 타입과 하이라이트 테이블(스키마만)
- 4개 타입 CRUD, 항목끼리 다대다 연결, 태그
- 태그 화면: 태그 목록(`/tags`)과 태그별 항목 보기(`/tags/[이름]`)
- 타입별 양식 (논문, 세미나, 연구)
- 홈 대시보드: 빠른 입력, 이어 읽기, 연구 단계별 칸반, 최근 생각, 최근 세미나
- PDF 뷰어 + 이어 읽기: 스크롤 위치 자동 저장, 다시 열면 마지막 위치로 이동
- 샘플 seed 데이터

### 2단계 (예정)

- 하이라이트와 메모 (PDF 텍스트 선택)
- 전체 검색 (`Cmd+K`): 제목, 본문, 하이라이트
- DOI·arXiv 링크로 논문 정보 자동 채우기 (Crossref, arXiv 공개 API)
- 라이너 스콜라 메모 (붙여넣기 저장, 라이너 바로 열기)
- 백링크

### 3단계

- 연결 관계 그래프 뷰 (`/graph`, 우주 보기 포함 — 완료)
- 데이터 내보내기와 백업은 하지 않습니다(범위 제외)

## 1단계 확인 체크리스트

실제 화면에서 아래를 차례로 확인합니다.

**설치와 실행**

- [ ] `npm ci` → `npm run db:migrate` → `npm run db:seed`가 오류 없이 끝난다 (dev 서버는 꺼 둔다)
- [ ] `npm run dev` 후 <http://127.0.0.1:3000>이 열리고 홈이 보인다
- [ ] 다른 Host 헤더로 접속하면 403 안내가 나온다 (예: `curl -H "Host: example.com" http://127.0.0.1:3000/`)

**홈**

- [ ] 빠른 입력창에 글을 쓰고 Enter를 누르면 "생각으로 저장했습니다."가 뜨고, 최근 생각 목록에 나타난다
- [ ] 이어 읽기 섹션에 읽는 중인 논문과 진행률 바가 보인다
- [ ] 진행 중인 연구가 단계별 칸으로 나뉘어 보인다
- [ ] 최근 세미나 목록이 보인다

**목록 (연구·논문·세미나·생각)**

- [ ] 표 보기와 카드 보기를 전환하고, 새로고침 뒤에도 선택이 남는다
- [ ] 상태·단계·종류 필터가 동작한다 (논문은 읽기 상태와 중요도, 생각은 종류와 발전 정도)
- [ ] 태그 필터가 동작한다
- [ ] 정렬이 동작한다

**새 항목과 양식**

- [ ] 연구·논문·세미나의 새 항목 화면에서 본문이 양식으로 미리 채워져 있다 (생각은 빈 본문)
- [ ] `N` 키로 현재 섹션의 새 항목 화면이 열린다

**상세와 편집**

- [ ] 연구·세미나·생각: 필드를 바꾸면 "저장 안 됨"이 뜨고, 저장 버튼 또는 Cmd+S(Windows/Linux는 Ctrl+S)로 "저장됨"이 된다
- [ ] 저장하지 않은 채 다른 페이지로 이동하거나 창을 닫으면 확인이 뜬다 (브라우저 뒤로 가기는 제외). 논문 상세도 같은 보호가 있다
- [ ] 논문: 입력을 멈추고 약 1초 뒤 자동 저장되며 "저장됨"으로 바뀐다
- [ ] 삭제는 확인 대화상자를 거친다

**연결과 태그**

- [ ] 상세 하단 "연결된 항목"에서 항목을 추가하면 양쪽 상세 화면에 모두 보인다
- [ ] 연결을 해제하면 양쪽 상세 화면에서 모두 사라진다
- [ ] `/tags`에 태그 목록과 개수가 보이고, 태그를 누르면 `/tags/[이름]`에 해당 항목이 모인다

**PDF 읽기**

- [ ] 논문 상세 또는 읽기 화면(`/papers/[id]/read`)에서 PDF를 올리면 뷰어가 열린다
- [ ] 스크롤하면 페이지가 이어지고, 확대/축소와 페이지 이동이 된다
- [ ] 읽던 곳에서 나갔다가 다시 열면 같은 페이지와 위치에서 시작한다
- [ ] 뒤로 가기 후 다시 들어가도 가장 최근 위치가 보인다

**화면과 단축키**

- [ ] 사이드바의 테마 토글에서 시스템 설정·라이트·다크를 바꾸면 바로 반영된다
- [ ] `N`은 목록과 상세에서 그 섹션의 새 항목 화면으로, 홈과 `/tags`에서는 새 생각 화면으로 간다
- [ ] `/`를 누르면 홈의 빠른 입력창으로 이동하고 포커스가 간다
- [ ] 텍스트 칸이나 에디터에 입력 중에는 단축키가 동작하지 않는다

## 테스트

- 단위 테스트: `npm run test`
- e2e 테스트: 처음 한 번 `npx playwright install chromium`을 실행한 뒤 `npx playwright test`를 실행합니다.
  - e2e는 `data/e2e/` 폴더를 매번 새로 만들어 그 안의 DB와 PDF를 씁니다. 로컬 데이터(`data/local.db`, `data/pdfs/`)와 분리되어 있습니다. `DATABASE_URL`은 `data/e2e` 안의 로컬 파일로 지정되므로 `.env`의 Turso 설정을 건드리지 않습니다. `BLOB_STORE=local`로 실행되어 `.env`에 R2가 설정돼 있어도 버킷에 쓰지 않습니다.
  - Playwright가 3000 포트에서 개발 서버를 직접 띄우므로, 실행 전에 `npm run dev`를 꺼 두세요. 켜져 있으면 포트가 충돌합니다.

## 데이터 백업

로컬 데이터는 `DATA_DIR`(기본 `data/`) 폴더에 있습니다 (`local.db`, `pdfs/`). 백업하려면:

1. 개발 서버를 끕니다 (`Ctrl+C`).
2. 데이터 폴더 전체를 다른 위치에 복사합니다.

DB를 쓰는 중에 복사하면 일부만 담길 수 있으므로 서버를 끈 뒤에 복사하세요. Turso 모드에서는 데이터가 원격 DB에, 공유 저장소를 쓰면 PDF·사진이 R2 버킷에 있으므로 이 방법으로는 백업되지 않습니다.
